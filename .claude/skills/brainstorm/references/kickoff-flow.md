# Kickoff Flow

Use this when a project is being shaped for the first time.

The point is not to ask every possible question. The point is to get to a sharp enough v1 that design and implementation can start without guesswork.

## 1. The Idea

Start here:

- What are you trying to build?
- What problem does it solve?
- What triggered the idea?
- Walk me through a concrete use case.
- What exists today: a manual process, another tool, or nothing?

Listen for whether this is really a tool, a workflow, a pipeline, or an exploration. The framing changes the build.

## 2. Context Check

Place the idea in context:

- Does it overlap with an existing project?
- Is it standalone or part of something larger?
- Who uses it?
- Where does it fit in daily or weekly work?

Also check for actor splits:

- Is there more than one type of user?
- Would different users see different content on the same surface?
- Are there different modes, even if the only user is you?

## 3. Scope Boundaries

Guard v1 aggressively:

- What is the minimum version that would be useful?
- What is explicitly not part of v1?
- If only one feature shipped, which one would justify the project?

Every "it should also..." gets captured for later unless the user can show that v1 is broken without it.

## 4. Technical Constraints

Lock the real constraints:

- What must this integrate with?
- What formats or platforms matter?
- Any hard limitations?
- Any performance requirements?
- Is this within current capabilities or a learning stretch?

Do not let technical assumptions sneak in untested. Name them.

## 5. Success Criteria

Make completion tangible:

- How will you know the project is useful?
- What is the first real task you will do with it?
- What would make you keep iterating versus abandon it?

If the answers are already obvious from the discussion, confirm them and move on.

## 6. Synthesis

End by producing:

1. a short reflection of what the project is
2. the main tensions or risks
3. a v1 boundary
4. a short future-ideas list
5. a next-step recommendation

Good kickoff output should make the next move obvious:

- write the design
- sketch the interface
- start implementing

If the next move is still unclear, the kickoff is not done yet.
