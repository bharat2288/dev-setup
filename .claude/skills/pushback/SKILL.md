# Pushback

Stress-test the proposal. Surface weak assumptions, risks, and missing questions.

## Process

1. Steel-man the proposal first. State why someone would choose it.
2. Identify the assumptions it relies on.
3. Find concrete failure modes, edge cases, or hidden tradeoffs.
4. Assess the biggest risks by likelihood, impact, and reversibility.
5. Ask whether the full solution is necessary, or whether a smaller move would do.
6. If the proposal still looks solid, say so. If not, suggest mitigations or alternatives.

## Rules

- Critique the idea, not the person.
- Prefer concrete scenarios over abstract warnings.
- The goal is sharper judgment, not debate theater.
- Do not invent alternatives unless the current approach has real weaknesses.

## Output Format

```markdown
## Understanding
[the strongest version of the proposal]

## Assumptions
- [assumption] - what if it is wrong?

## Failure Modes
- [specific scenario]

## Risks
- [risk] (likelihood: H/M/L, impact: H/M/L, reversibility: easy/hard/irreversible)

## Questions to Resolve
- [question]

## Verdict
[proceed / proceed with mitigations / reconsider]
```

## When to Use

- strategy or scope decisions
- before expensive or hard-to-reverse work
- when something feels too neat
- when you explicitly want critique before committing
